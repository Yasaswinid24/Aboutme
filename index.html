02 · Project 01

Medical Speech → Clinical Note

Reducing the documentation burden on physicians.

Six-person engineering team · I built this pipeline end to end
→ → → →
01The problem

Physicians spend significant time documenting each patient encounter. Instead of typing the note by hand, the physician speaks naturally — the system converts that speech into a structured clinical note.

Doctor speaks→ Manual documentation→ Time-consuming
03What went wrong / what I learned
✕ Failure

General-purpose Whisper / Wav2Vec2 models — trained on everyday speech — didn't perform well enough on medical audio.

✓ Learning

Domain-specific data matters. Fine-tuning on medical audio fixed it.

✕ Failure

LLM output can't be trusted as final — errors can silently propagate through a pipeline.

✓ Learning

The model generates. The system checks. The physician decides.

The generated note passes through automated validation — checks on structure and clinical content — before the physician ever sees it, and it's only stored after the physician approves it. If I kept improving this system, I'd evaluate each stage separately (ASR, structuring, validation) to see exactly where the remaining errors come from, since improving the LLM alone isn't enough when errors can enter at any stage.
04Result / impact
~25 minsaved per doctor / session

The physician speaks instead of typing the full note — review still happens before anything is stored.

03What went wrong / what I learned
✕ Failure

RAG on my own CV retrieved only the top-3 chunks per job — the model saw roughly 20% of my CV, so real skills got reported as "missing."

✓ Learning

A ~480-word CV doesn't need retrieval. Sending it in full fixed the scoring — retrieval is for corpora that exceed the context window.

Before
CV (full text) ↓ Chunk + embed (RAG) ↓ LLM sees ~20% of CV
After
CV (full text) ↓ Sent whole, no retrieval ↓ LLM sees 100% of CV
Also along the way — most job sites blocked reliable scraping, so I standardised on the Bundesagentur für Arbeit's public API. And a fixed 3,000-character truncation was cutting off qualification sections that sit later in a posting, so the LLM was scoring jobs on incomplete text — fixed by capturing the full description before any truncation happens.
I also added a code-level check that re-verifies every "missing skill" the model reports against the literal CV text — if the model still misjudges a match, this catches it before it reaches me. The architecture changed because the system's own failures showed me what information the model actually needed, not the other way around.

03What went wrong / what I learned
✕ Failure

An early Stage-2 model looked strong overall — 87.5% accuracy — but caught only 40% of real interview emails, missing 6 of 10.

✓ Learning

A model can look strong on average while failing the one class that matters most. Accuracy alone isn't enough.

Also along the way — no ready-made dataset matched this exact use case, so I built and labelled my own from real Gmail data. Every email is written differently too, which made patterns harder to learn from a small dataset.
Fix: rebalanced the training data and moved the harder Stage-2 intent task from the CNN to a fine-tuned XLM-RoBERTa transformer — interview-class recall rose to roughly 90% after re-evaluation. The CNN stayed the right choice for the coarser Stage-1 job/non-job filter; it was only the harder, imbalanced Stage-2 task that needed the transformer.

06 · AI in Pharma

How AI & LLMs could create value in pharma

The simple story I would tell: pharma creates a lot of scientific information. AI can help turn that information into something researchers can use faster — while keeping scientific judgement with people.

The information chain
Disease → Clinical trial → Data → Evidence → Decision

In areas such as cardiovascular, renal and metabolic disease, patient populations and clinical endpoints can be complex and interconnected. That creates a lot of information that has to be collected, structured, analysed and interpreted.

1. Make information usable Use NLP and LLMs to extract and structure information from clinical reports, literature and other scientific documents.
2. Give researchers a faster first pass Support tasks such as literature synthesis, finding relevant evidence and drafting from structured study outputs — so scientists spend more time on interpretation.
“I don't see AI replacing scientific judgement. I see it reducing repetitive information work, so researchers can spend more time on the scientific questions and decisions that matter.”
WHY THIS INTERESTS ME

From unstructured information → structured evidence

That connects directly to my healthcare AI experience. I have already worked on turning unstructured clinical speech into structured information. In pharma, I see a similar opportunity with clinical-study information: documents → structured data → validated evidence.

07 · My Approach

How I would use AI responsibly

My projects taught me that the important question is not only “Can the model do it?” but “Can we trust the result enough to use it?”

Four-step framework
01

Start narrow

Pick one useful, measurable problem rather than trying to automate everything.

02

Ground it

Keep important outputs connected to the underlying data, study results or literature.

03

Validate it

Test the failure cases that actually matter and add checks around the model.

04 · Keep the scientist in control
The AI can assist, but the final scientific decision should remain with the appropriate expert.
One concrete example

Clinical study report → machine-readable information

One use case I would explore is using an LLM to help turn large clinical-study reports into structured information — for example population, treatment, endpoints, outcomes and adverse events.

Study documents→ NLP / LLM→ Structured information→ Validation→ Scientific review
“The model generates → the system checks → the scientist decides.”
